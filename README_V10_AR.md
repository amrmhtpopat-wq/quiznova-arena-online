# QuizNova Arena V10 — Cloud-Ready Edition

هذه نسخة تطوير جديدة تستهدف الاستضافة السحابية متعددة المعلمين، مع شاشة قيادة رئيسية وشخصيات 3D. تم اختبار وظائفها محليًا باستخدام SQLite. **لا تُعد النسخة منشورةً سحابيًا بمجرد تشغيلها محليًا**؛ لا بد من توصيل قاعدة PostgreSQL مستقلة وتشغيل اختبار فعلي على الاستضافة.

## الجديد

- تسجيل حساب مستقل لكل معلم، مع نوع المدرسة (بنين، بنات، مختلطة) والمادة.
- صفحة البداية الرئيسية Dashboard بعد دخول المعلم، وبها النتائج والشعب والمهارات والطلاب.
- 32 شخصية 3D منفصلة من التصاميم المعتمدة: 16 للأولاد و16 للبنات، تظهر حسب نوع المدرسة. وهي **صور رمزية ثلاثية الأبعاد المظهر** وليست نماذج 3D قابلة للدوران.
- إمكانية الدخول بالاسم والصورة، وبطاقات QR **اختيارية** وليست إلزامية حتى عند إخفاء نتائج الامتحان.
- انتهـاء السؤال آليًا عند انتهاء الوقت أو إجابة الجميع، مع زر تخطي يدوي.
- وضع الامتحان بدون كشف النتائج المبكرة، والتعاون، وحرب الشعب، ونقاط XP والمستويات، وتحليل إتقان المهارات.
- حفظ اختبارات وطلاب وسجل نتائج كل معلم في قاعدة SQLite محليًا أو PostgreSQL على السحابة.
- حفظ حالة الغرف النشطة في قاعدة البيانات لاستعادتها بعد إعادة تشغيل نسخة الخادم الواحدة.
- زر **«نسخة بياناتي»** داخل لوحة القيادة لتنزيل نسخة JSON من بيانات المعلم وتقاريره وطلابه.
- فحص /api/health يختبر الاتصال الحقيقي بقاعدة البيانات ويعيد 503 عند تعذر الوصول إليها.

## تشغيل محلي

1. يجب وجود Python 3.10+.
2. فك ضغط الملفات ثم شغّل `START_QUIZNOVA_V9.bat` (اسم ملف التشغيل محفوظ للتوافق مع النسخة السابقة)، أو `python server.py`.
3. افتح `http://localhost:8765/`.
4. للحفاظ على حساب V9 القديم: ضع ملف `quiznova_local.db` الأصلي **كملف مستقل في نفس مجلد V10** بعد عمل نسخة احتياطية منه وقبل أول تشغيل. لا تنقل قاعدة أثناء تشغيل الخادم.

## نشر V10 على الإنترنت

**لا تستبدل خدمة V8 الحالية مباشرة.** أنشئ فرع `v10-staging` وخدمة جديدة للتجربة حتى يتم التحقق من الاتصال والتحويل.

1. أنشئ قاعدة بيانات Neon PostgreSQL مستقلة للمشروع، في منطقة قريبة من مستخدمي الأردن عند توفرها.
2. احفظ `DATABASE_URL` كمتغير بيئة سري في Render **وليس في GitHub أو ملفات الواجهة أو الدردشة**.
3. صِل الخدمة الجديدة بمستودع GitHub وفرع `v10-staging`، واضبط:
   - Runtime: Python
   - Build: `pip install -r requirements.txt`
   - Start: `python server.py`
   - Health Check: `/api/health`
   - Region: Frankfurt عند توفرها.
4. افتح `/api/health`: يجب أن يعرض `version: 10.0`, `storage: postgres`, `database: ready`.
5. سجّل حسابين للمعلمين بمواد مختلفة، أنشئ غرفة، أدخل خمسة طلاب، أنهِ المسابقة، أعد تشغيل الخدمة، وتأكد من بقاء الحسابات والنتائج.
6. لا تنقل الرابط الرئيسي إلى V10 قبل اختبار جميع الخطوات السابقة وأخذ نسخة احتياطية.

## نقل بيانات V9.3 إلى قاعدة Neon جديدة

- لا ترفع `quiznova_local.db` أو رابط الاتصال إلى GitHub.
- شغّل: `python MIGRATE_LOCAL_TO_NEON.py --source /path/to/quiznova_local.db` لمعاينة عدد السجلات دون تعديل.
- عند جاهزية قاعدة جديدة **فارغة تمامًا**، يمكن تشغيل نفس الأمر مع `--apply`، بعد ضبط `DATABASE_URL` بصورة آمنة على جهاز موثوق.
- الأداة تتحقق من خلو الوجهة، وتحفظ بيانات الحسابات والطلاب والنتائج في معاملة واحدة، وتلغي العملية بالكامل إذا ظهر تعارض. لا تنقل جلسات الدخول أو غرف الاختبار النشطة.

## اعتبارات مهمة قبل الاستخدام اليومي

- قواعد Neon المجانية لها حدود استخدام وسعة، وتحتاج رصدًا ونسخًا احتياطيًا منفصلًا. الديمومة تعني بقاء بيانات PostgreSQL بين عمليات إعادة نشر خادم Render، **ولا تعني ضمانًا مطلقًا ضد الأعطال أو الحذف**.
- الغرف المباشرة تعود من قاعدة البيانات بعد إعادة التشغيل ضمن حدود الاحتفاظ، بشرط تشغيل **نسخة خادم واحدة** فقط، وعدم حذف قاعدة البيانات.
- الامتحانات التي تسمح بالدخول بالاسم لا تستطيع إثبات هوية الطالب أو منع إعادة المحاولة باستخدام اسم مختلف؛ تستلزم الاختبارات الرسمية آلية تحقق أقوى عند الحاجة.
- لم تُضف بعد استعادة كلمة مرور بالبريد الإلكتروني، أو نظام تحقق هوية المعلمين، أو صلاحيات مدير مؤسسة، أو تدقيق أمني خارجي شامل. لا تخزن علامات رسمية حساسة قبل معالجة هذه المتطلبات وحماية بيانات الطلاب وفق سياسة المدرسة.
- الملف `render.yaml` يحتوي اسم الخدمة الافتراضي للنسخة القديمة؛ عند الاستضافة عبر لوحة التحكم استخدم **اسم خدمة جديدًا** لتجنب استبدال المنصة المنشورة.
